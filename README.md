# DnepritNewsletter

Компонент email-розсилок для MODX Revolution 2.8.1.

## Реалізовано

- стандартна структура MODX Extra;
- xPDO-схема для підписників, кампаній, черги та журналу;
- сервісний клас компонента;
- CMP-контролер і пункт меню;
- transport package builder;
- resolver для створення й оновлення таблиць;
- серверний список підписників із пошуком і фільтрацією;
- додавання та редагування підписників через ExtJS-вікно;
- перевірка й нормалізація email;
- захист від дублікатів;
- активація, відписка та блокування;
- групова зміна статусу й масове видалення;
- імпорт підписників із CSV/TXT;
- автоматичне визначення роздільника та підтримка UTF-8/Windows-1251;
- попередній перегляд і вибір колонок Email/Ім’я;
- пропуск або оновлення дублікатів;
- опціональна повторна активація відписаних;
- підсумковий звіт імпорту;
- список email-кампаній із пошуком і фільтрацією;
- створення, редагування, копіювання та видалення чернеток;
- візуальний HTML-редактор і окрема текстова версія листа;
- налаштування відправника та Reply-To;
- формування персональної черги з активних підписників;
- негайний або запланований старт відправлення;
- транзакційний захист від повторного створення черги;
- персональна заміна плейсхолдерів у темі, HTML і тексті;
- збереження повного знімка листа в кожному записі черги;
- пакетна відправка через CLI Cron;
- блокування паралельних запусків і резервування записів черги;
- хвилинні та погодинні ліміти;
- повторні спроби з експоненційною затримкою;
- повторна перевірка статусу підписника перед відправленням;
- статистика надісланих, помилкових і пропущених листів;
- блокування редагування кампанії після підготовки до відправлення;
- український і російський інтерфейс.

## Формати імпорту

Підтримуються файли `.csv` і `.txt` розміром до 10 МБ за замовчуванням. Для CSV автоматично визначаються кома, крапка з комою, табуляція або вертикальна риска. TXT без роздільників обробляється як один email у кожному рядку.

Максимальний розмір файлу налаштовується системним параметром:

```text
dnepritnewsletter.import_max_size
```

Тимчасові файли зберігаються в `core/cache/dnepritnewsletter/imports/`, недоступні з публічної директорії та автоматично видаляються після імпорту або через 24 години.

## Плейсхолдери листа

У темі, HTML-версії та текстовій версії можна використовувати:

```text
[[+name]]
[[+email]]
[[+unsubscribe_url]]
[[+site_name]]
```

Під час формування черги плейсхолдери замінюються даними конкретного підписника. Значення для HTML екрануються, а тема очищується від переносів рядка та обмежується 255 символами.

## Формування черги

Чергу можна сформувати лише для кампанії зі статусом `draft`. До неї потрапляють тільки підписники зі статусом `active`. Для кожного одержувача зберігаються персональні тема, HTML, текст, відправник і Reply-To.

Поле `next_attempt_at` містить час, після якого Cron може забрати лист у роботу. При негайному запуску використовується поточний час, при плануванні — вибрана дата й час. Після успішного формування кампанія переходить у статус `queued` або `scheduled` і більше не редагується.

URL відписки формується через ресурс із системного налаштування:

```text
dnepritnewsletter.unsubscribe_resource_id
```

Якщо ресурс не вказаний, використовується головна адреса сайту з параметром `newsletter_token`.

## Налаштування пошти

Відправник використовує стандартний поштовий сервіс MODX `modPHPMailer`. SMTP налаштовується штатними системними параметрами MODX, зокрема `mail_use_smtp`, `mail_smtp_hosts`, `mail_smtp_port`, `mail_smtp_user`, `mail_smtp_pass` і `mail_smtp_prefix`.

Кожен лист передає HTML-версію та текстову альтернативу. Після кожної спроби поштовий об’єкт очищається, щоб адресати або Reply-To не переходили до наступного листа.

## Налаштування Cron

Запускайте worker щохвилини:

```cron
* * * * * /usr/bin/php /path/to/site/core/components/dnepritnewsletter/cron/send.php >> /path/to/site/core/cache/logs/dnepritnewsletter-cron.log 2>&1
```

Для нестандартно розташованого `core` або якщо скрипт не може сам знайти корінь MODX, передайте `MODX_BASE_PATH`:

```cron
* * * * * MODX_BASE_PATH=/path/to/site /usr/bin/php /custom/core/components/dnepritnewsletter/cron/send.php
```

Разовий запуск із власним обмеженням пачки:

```bash
php core/components/dnepritnewsletter/cron/send.php --limit=20
```

Worker використовує файлове блокування `core/cache/dnepritnewsletter/sender.lock`. Другий паралельний запуск завершується без обробки. Записи додатково резервуються в базі через `status=processing`, `locked_at` і `locked_by`.

## Ліміти та повторні спроби

```text
dnepritnewsletter.batch_size         50
dnepritnewsletter.limit_per_minute   50
dnepritnewsletter.limit_per_hour     500
dnepritnewsletter.max_attempts       3
dnepritnewsletter.retry_delay        300
dnepritnewsletter.lock_ttl           3600
```

Значення `0` для хвилинного або погодинного ліміту вимикає відповідне обмеження. Затримка повторів зростає експоненційно: при базових 300 секундах — 5, 10, 20 хвилин, але не більше 24 годин. Після `max_attempts` запис отримує статус `failed`.

Перед фактичним надсиланням worker повторно перевіряє підписника. Якщо він уже відписаний, заблокований або видалений, лист отримує статус `skipped` і не надсилається.

Застарілі блокування `processing`, старші за `lock_ttl`, повертаються до статусу `pending`. Це відновлює чергу після аварійного завершення PHP-процесу.

## Гарантія доставки

Черга реалізує доставку типу **at least once**. У звичайній роботі блокування захищає від дублів. Проте якщо SMTP вже прийняв лист, а відразу після цього база даних стала недоступною і статус `sent` не зберігся, запис буде повернуто в чергу після завершення `lock_ttl` і може бути надісланий повторно. Повністю виключити такий випадок можна лише через зовнішнього провайдера з ідемпотентним API та власним ідентифікатором повідомлення.

## Збірка пакета

1. Розмістіть репозиторій у корені тестової установки MODX або передайте шлях через змінну середовища `MODX_BASE_PATH`.
2. Запустіть:

```bash
php _build/build.transport.php
```

Готовий transport package буде створено у стандартній директорії пакетів MODX: `core/packages/`.
